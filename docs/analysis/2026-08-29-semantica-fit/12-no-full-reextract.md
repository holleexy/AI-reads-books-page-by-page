# 既存コーパスは取り直さない

判断日は 2026-08-30 である。
すでに読んだ知識点を、ページ番号のために全部取り直すことはしない。
ページ番号はこれから読む分に付ける。
既存の命題は、冊名付きのまま下流（関係取り、グラフ）に使う。

## なぜ全部取り直しはしないか

2026-08-30 時点の知識 JSON は 51 冊、106,414 件である。
すべて文字列である。
ページ付きの件は 0 である。

取り直しには、同じページを LLM へもう一度渡す費用と時間が乗る。
このマシンに PDF が残っているのは 9 冊だけである。
その 9 冊でも処理済みページは合計 3,282 である。
残り 42 冊は PDF がここには無い。
取り直し以前に、入力が揃っていない。

命題はページ本文の写しではない。
LLM が言い換えた文である。
日本語の本でも、英語の命題になっている件が多い。
PDF の文字を検索してページを後付けすることは、再現性が低い。
推測でページを埋めることはしない。

## 出典の二層

出典は次の二層である。
ページが無いことを、冊まで捨てる理由にはしない。

| 層 | 付く対象 | 役割 |
| --- | --- | --- |
| 冊 | すべての知識点 | どの本の JSON から来たかを示す。`book_key` で足りる |
| ページ | これから読む分 | その本の何ページかを示す。グラフ項目の検証に使う |

既存件の出典は冊までである。
新規件の出典は冊とページである。
Semantica の出自記録も、入力にある層だけを付ける。
無いページを補完しない。

## これから読む分

抽出の保存形式は `{"text", "page"}` のままである。
手順は [ページ番号は必須である](11-page-provenance.md) に書いた。
既存 JSON を `{text, page: null}` へ一括変換する作業はしない。
読込時に正規化する。

途中再開で旧件と新規件が混ざることはある。
旧件の `page` は埋まらない。
混在を避けるために既存 JSON を消すことはしない。

## 下流に渡すとき

関係取りとグラフは、既存の命題と要約を入力にする。
ページ待ちでは始めない。
項目から元ページへ戻れるのは、ページ付きの件に限る。
ページが無い件は、元の冊の JSON と要約まで戻れる。
