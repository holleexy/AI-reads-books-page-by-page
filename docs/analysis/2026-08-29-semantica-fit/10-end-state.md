# 全部やったあとに実現する状態

調査日は 2026-08-30 である。
「全部」は次を指す。本を読む仕組みはそのまま残す。Hermes に入っている Semantica で関係を取る。xAI をつなぐ。本用の記録は別ファイルにする。これから読む分にページ番号を付ける（既存件は取り直さない）。1 冊で形を確認してから冊を増やす。冊をまたいだ同一概念の統合まで行う。

## いまと、全部やったあと

いまは、本ごとに「短い命題の列」と「要約」がある。
人は要約を読んで全体を知る。
機械は「労務と人材マネジメントはどう違うか」を、結びとして辿れない。

全部やったあとは、命題と要約に加えて、次が残る。

- 本に出てくる対象（概念、人、制度、枠組み）が、種類付きの項目になる
- 対象同士の関係が、向きのある結びとして残る
- その本（または分野）で使う種類の一覧（クラスと、種類同士の関係）がファイルになる
- 画面で項目と結びを辿れる
- 「A と B はどういう関係か」を機械に尋ねられる
- 言い直しの重複はまとめられ、食い違いは印が付く
- 項目から元のページへ戻れる（ページ付きの件に限る。既存件は冊まで）

Hermes の作業記録（決めたこと、残した事実）は別のままである。
本の項目はそこに混ざらない。

## 1 冊でできること

『労務入門』を例にする。
いまは 2,328 件の命題と、1 本の要約がある。

全部やったあと、同じ冊について次ができる。

- 「労務」と「人材マネジメント」が別項目として出る
- 「労務は 6 つの要素を持つ」が結びとして残る
- 要素（ルール、労働時間と対価、生活と健康、雇用、労使関係、労務体制）が項目としてぶら下がる
- 画面でその結びを辿る
- 「労務の構成要素は何か」と尋ねると、要約を最初から読み直さずに答えの候補が返る

種類の一覧は、英語の医療や金融の既成型ではない。
その本の要約と命題から、日本語で推定した一覧である。
専門家が手で固めた分類ではない。
誤りや粗い括りは残り得る。
推定結果を見て直す前提である。

## 複数冊でできること

統合までやると、冊をまたいでも同じ対象は 1 項目に寄る。
『労務入門』の「労務」と『採用入門』の「労務」が、別々の文字列ではなく、同じ対象への言及として残る。
「この概念を、どの本がどう述べているか」を辿れる。
食い違う定義には印が付く。

統合の前は、冊ごとに別グラフである。
著者ごとの用語の揺れが解けない。
統合は最後である。

## 残る成果物

本を読む側のフォルダに、いまあるものに加えて次が並ぶ。

| 種類 | 中身 |
| --- | --- |
| 知識 JSON（既存） | 短い命題。新規分はページ番号付き。既存件はページ無し |
| 要約 Markdown（既存） | 冊の全体像 |
| グラフファイル（新規） | 項目と結び |
| 種類のファイル（新規） | クラスと関係の定義（OWL / SHACL） |
| 画面（新規） | 本用のファイルを指した表示 |

これから読む分にはページ番号が付く。
すでに読んだ約 10 万件は、ページへ戻せない。
取り直さない。
既存件の出典は冊までである。
詳細は [既存コーパスは取り直さない](12-no-full-reextract.md) に書いた。

## 全部やっても起きないこと

本を読む作業は無くならない。
画面と検索は、命題から作った関係を辿る装置である。
PDF の全文を、人が読む代わりにはならない。

Hermes が「昨日決めたこと」を思い出す対象は、本のグラフに置き換わらない。
作業記録と本の記録は別である。

与信や医療の監査向けの決定履歴は、この作業の範囲に入らない。
本の学習には、その種の「決定」オブジェクトが無い。

英語向けの機械的な固有名抽出だけでは、この状態にはならない。
xAI による日本語の関係取りが前提である。
