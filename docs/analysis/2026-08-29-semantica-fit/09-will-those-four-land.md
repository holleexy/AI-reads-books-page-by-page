# 挙げた 4 項目は、Hermes の Semantica を呼べば実現するか

調査日は 2026-08-30 である。
「それ」は次を指す。プログラム本体は Hermes に入っている Semantica 0.6.5 を使う。本の関係一覧は別ファイルへ書く。日本語用に xAI をつなぐ。

結論は、4 項目とも「モジュールはある」。
いまの知識 JSON を渡した瞬間に全部揃う、ではない。

## 項目ごとの判定

| 挙げた項目 | 実現するか | 条件 |
| --- | --- | --- |
| 型付きエンティティと関係（辺） | 条件付きでできる | 英語向けのパターン抽出だけでは足りない。文章を読む AI（xAI）で取る |
| クラスとプロパティのオントロジー（OWL / SHACL） | 条件付きでできる | 日本語は要約からクラスを推定する。労務や採用の既成型は入っていない。Hermes 既存の SHACL は「決めたこと」「人」用であり、本の型ではない |
| ナレッジグラフの構築、可視化、問い合わせ | 条件付きでできる | 構築はできる。画面と検索は、本用のファイルを指す必要がある。いま動いている画面（ポート 8766）は Hermes の作業記録 165 件向けである |
| 意味的デデュープ、矛盾検出、出典（PROV-O） | 条件付きでできる | 近い文のまとめと矛盾フラグは呼べる。ページ番号は新規抽出に付ける。既存件の出典は冊まで。取り直さない |

## いまの入力が制限するもの

新規抽出の知識点は `{"text", "page"}` である。
すでに読んだ約 10 万件は文字列のままである。
ページへは戻せない。
取り直さない。
出典の層は [既存コーパスは取り直さない](12-no-full-reextract.md) に書いた。

日本語の概念（労務と人材マネジメントの違いなど）は、固有名抽出だけではクラスにならない。
xAI をつないだ LLM 抽出が前提である。
48 冊相当を一度に渡すと品質と費用が崩れる。
1 冊（要約でクラス、知識点の一部で関係）で形を見てから広げる。

## やれば揃うものと、追加作業が要るもの

揃う。

- 1 冊から「もの」と「関係」を出す
- クラス一覧を OWL / SHACL ファイルとして書き出す
- 別ファイルのグラフを作り、そこを画面と検索の対象にする
- 近い重複の検出、矛盾の検出をそのグラフにかける

追加が要る。

- xAI を Semantica から呼ぶ接続
- 本用のグラフファイルと、本用の画面

Hermes の作業記録へ本を流し込めば 4 項目が揃う、ではない。
プログラムは同じで、記録の置き場と入力の形が別である。
