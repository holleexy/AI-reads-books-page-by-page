# ページ番号は必須である

判断日は 2026-08-30 である。
これから読む分には、ページ番号を付ける。
既存の約 10 万件を、ページのために取り直すことはしない。
既存件の扱いは [既存コーパスは取り直さない](12-no-full-reextract.md) に書いた。

## なぜ新規分には必須か

グラフの項目は、元のページへ辿れて初めて、そのページで検証できる。
ページが無い命題は、本のどの箇所から来たかを後から復元できない。
Semantica の出自記録（PROV-O）も、入力にページが無ければページ層を付けられない。

ページ番号は LLM に推測させない。
モデルは命題の文字列だけを返す。
付けた番号は、そのとき処理していた PDF ページである。

## 保存の形

新規抽出は次の形で書く。

```json
{
  "knowledge": [
    {"text": "労務は義務を果たすことである", "page": 12}
  ]
}
```

`page` は PDF の 1 始まりである。
ログの `Processing page N` と同じ番号である。
内部の処理添字は 0 始まりのままである。
保存時に +1 する。

旧形式の文字列は、読込時に `{"text": "...", "page": null}` になる。
途中再開すると、旧件は `null`、新規件は番号付きで混在する。
混在は許容する。
既存 JSON を消して取り直すことは、既定の作業ではない。

## 既存コーパス

すでに読んだ知識点はページを持たない。
推測でページを埋めることはしない。
51 冊、106,414 件を取り直すことはしない。
このマシンに PDF があるのは 9 冊である。
残りは入力が無い。
