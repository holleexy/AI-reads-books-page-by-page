# end-state の上に DeepTutor を足すと広がるか

調査日は 2026-08-30 である。
対象は [全部やったあとに実現する状態](10-end-state.md) と、同じマシンの DeepTutor（`/opt/deeptutor`、Hermes ランタイム）。

結論は、**広がる。ただし別の層である。**
end-state は本の中身の地図である。
DeepTutor は学ぶ側の練習である。
地図ができたあとに練習を足すと、いま end-state が明示的に持たないものが出る。
地図の代わりにはならない。

## end-state がすでに持つもの

- 対象が種類付きの項目になる
- 向きのある結びを辿れる
- 「A と B はどういう関係か」を機械に尋ねられる
- 言い直しはまとまり、食い違いは印が付く
- 新規件はページへ戻れる。既存件は冊まで

ここまでで足りる問いは、構造の問いである。
「労務の構成要素は何か」「採用入門の労務と労務入門の労務は同じか」。

## end-state が持たないと書いてあるもの

[10-end-state.md](10-end-state.md) は、画面と検索を「命題から作った関係を辿る装置」と限定している。
PDF の代わりにはならない。
Hermes の作業記録の代わりにもならない。
与信や医療の決定オブジェクトも無い。

次はどちらにも無い。対応表では「両方なし」に近い。

- 自分がどこまで覚えたかの記録
- 診断、説明、自分の言葉での確認、演習、間隔復習
- 引用つきで本に聞く対話（グラフ走査とは別）
- 食い違いを材料にしたクイズ

DeepTutor はここを担当する。

## 足すと新たにできること

地図がある前提で DeepTutor を使うと、次が足せる。

1. **地図をカリキュラムにする。**
   「労務は 6 要素を持つ」という結びが、Mastery のモジュールになる。
   2328 件の命題を全部ポイントにしない。
   グラフのクラスと辺が、何をどの順で練習するかの骨格になる。

2. **食い違いを問題にする。**
   統合で印が付いた定義差を、クイズにする。
   「この本はこう言い、あの本はこう言う。現場ではどちらを先に見るか」が、グラフのフラグから出る。

3. **構造の問いと、本文の問いを分ける。**
   「労務と人材マネジメントはどう違うか」はグラフへ。
   「その説明は何ページの図か」「条文の言い回しは何か」は OCR PDF の KB へ。
   end-state だけでは、既存件はページに戻れない。
   DeepTutor の KB は PDF 側を残すので、新規件以外でも本文に聞ける。

4. **横断した項目を、一つの練習対象にする。**
   冊をまたいで寄った「労務」は、クイズも 1 項目で足りる。
   冊ごとの言い直しを別々に暗記しなくてよい。

5. **学ぶ側の記憶を、本の地図と分けて残す。**
   DeepTutor の Memory は「自分が間違えた点」である。
   Semantica のグラフは「本が述べている対象」である。
   Hermes の作業記録とも、どちらにも混ぜない。
   三層のままが、end-state の「本は混ぜない」と両立する。

## 広がらないこと・やらないこと

DeepTutor を足しても、オントロジー推定、OWL、矛盾検出、冊横断の同一項目統合は増えない。
それは Semantica 下流の仕事である。

PDF を DeepTutor の KB に載せるだけなら、end-state より前の「本に聞く」に戻る。
グラフ無しの対話はできる。
「種類付きの項目として辿る」はできない。

同じ PDF を Semantica と DeepTutor の両方で抽出し直さない。
入力の正本は、いまどおり知識 JSON と要約と OCR PDF である。

2000 件超の命題を Mastery に無加工で流さない。
束ねる単位は、グラフのクラスとモジュールである。
